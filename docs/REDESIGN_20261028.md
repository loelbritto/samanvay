# Samanvay redesign — 28 October 2026

**Implemented and code-checked; browser acceptance remains open.** Earlier Stage 1/9 screenshots and browser checks cover the earlier interface. They do not validate this redesign at desktop, mobile, keyboard-only navigation or actual 200% zoom.

## Request and pre-edit assessment

The user's direct feedback was “Too many controls and technical terms.” Source inspection found eight equally prominent navigation links, always-visible filters using internal IDs, action forms with irrelevant fields, raw evidence/action JSON, repeated technical warnings, coordination plans and pair reviews on one long page, and notification history without an unread view. The persistent backend already existed; rebuilding it was unnecessary.

The newly supplied attachment, `C:/Users/loelb/.codex/attachments/67d544ca-859a-48f4-9bb5-4cb54f6a4740/Pasted text.txt`, informed the design. Its contents are not independent proof of official SIH requirements or authority for external actions. No agents, paid services, external messages or hosting were used.

Three approaches were considered: a task-first workspace; separate institution-plan/evidence-comparison views; an institution graph with action-overlap warnings. The first two directly address the feedback using implemented data. A graph would add controls, while overlap warnings require additional validated logic, so neither was added.

## Implemented changes

- Calmer green/neutral visual system, five primary navigation links, separate utilities and a mobile menu. One persistent strip labels fictional data, the student prototype and no AICTE connection; it also identifies an advanced demo clock.
- Plain-language roles/statuses. Demo account buttons fill the login form, followed by real server authentication. New-complaint links appear only for intake-eligible officer roles.
- Overview leads with actual workload counts and open-case next steps/owners/deadlines. Its attention list explicitly covers only the API's 20 most recent cases. The misleading Pending link to an unfiltered list was removed.
- Search and status are immediately available; institution/bureau/region/category/date filters are secondary, using readable choices. Cases use responsive rows/cards and 25-record pagination.
- Case detail prioritises owner, status, due date and next step. Current description is distinguished from preserved original submission. History, files, checksums and prior actions remain accessible.
- Case action choices follow role/capability and state. Only relevant inputs appear for information requests, correction, closure, deadline and reopening. Server authorisation/version checks remain authoritative. Pending transfers suppress closure; transfer and reassignment remain separate secondary actions.
- Coordination separates Institution plans from Compare complaints. Plans identify the coordination lead and individual case owners separately. Available plan stages follow the server transition rules; a plan update preserves its existing deadline.
- Comparisons show source text and readable supporting, different and missing evidence with case links. Reviewers must choose a relationship and explain it; there is no preselected relationship. Completed decisions remain immutable; stale evidence offers a linked current comparison. Manual source reviews and rule-generated suggestions are labelled separately. Technical method/reference details are secondary.
- Reports lead with four counts and Summary/Breakdowns/Activity views. Formula details and case rows are secondary. CSV, print and case drill-down retain identical filters. Old report data is cleared when filters change.
- Notifications default to delivered unread reminders, retain full history and show 20 at a time. Read acknowledgement still persists to the server. Transfers default to awaiting acceptance with a full-history view.
- Institution lookup/corrections and activity are secondary. Successful corrections refresh case/institution resources. Help explains the four separate concepts; administrator tools and the old static preview are secondary.

Every complaint remains distinct. Institution identity, complaint relationships, case owners and coordination leads still use separate persistent backend records. No backend source, schema, seed, research corpus, dependency lockfile or historical preview source changed.

## Remaining gate and next phase

The redesign gate is **not ready to close** until browser access works and these checks are observed:

1. Desktop and narrow layouts for login, overview, cases/filter/intake, case detail/history/actions, institutions, plans/comparisons, transfers, reports, notifications and help/admin.
2. Keyboard menu/skip-link/navigation, disclosures, comparison selector-to-detail focus, relevant action fields, validation, pagination and sign-out.
3. Actual browser 200% zoom, including long references/evidence, the comparison form and report exports. A narrow viewport is not zoom evidence.
4. UI write rehearsal in a separate marked context: case update, transfer, pair review, plan, identity correction and notification acknowledgement. API tests do not prove the rewritten browser handlers work end to end.
5. An unfamiliar user identifies the institution coordinator, case owner and next step, and distinguishes RELATED from DUPLICATE for different people/receipts in the same incident. The user's reported confusion is feedback, not a completed usability study.

The tool still reports a saved origin permission block despite the user's approval. That permission must actually be resolved before browser checks can proceed; repeated confirmation has not resolved it. No further permission was requested in this pass.

Backend limits remain: local SQLite/HTTP demo accounts; no verified PostgreSQL/RLS or production deployment; no official AICTE/email integration, semantic/LLM service or real malware scanner; no production security/load or screen-reader certification. The overview attention set is bounded to 20 recent cases and comparison/identity selectors to 200, with limits disclosed. Reports are current-state cohorts and period events, not historical-state reconstruction. No new backend feature or evaluation metric is claimed.
